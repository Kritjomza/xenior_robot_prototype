# DeltaX Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the authenticated, saved, simulation-first DeltaX robot workspace while preserving Phase 1 behavior.

**Architecture:** Extend the FastAPI runtime with verified identity, persistent project contracts, server-owned safety, kinematics, jog, and optional RoboDK adapters. Replace the React mock surface with a guarded shell whose DSL and Blockly editors share `RobotProgramV1` and live state.

**Tech Stack:** Python 3.10, FastAPI, Pydantic, PyJWT/cryptography, React 19, TypeScript 5.9, Vite 8, Supabase JS, Monaco, Blockly, Vitest, pytest, Playwright, PostgreSQL/RLS.

**Spec:** `docs/superpowers/specs/2026-09-15-phase-2-design.md`

## Global Constraints

- Preserve every Phase 1 API, `RobotProgramV1`, Mock adapter behavior, WebSocket behavior, and test.
- Keep `mock` default; expose no physical robot or Raspberry Pi execution path.
- Use `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`; never expose a service-role key.
- Use TDD for domain, authentication, persistence, safety, kinematics, and adapter behavior.
- Label geometry as simulation defaults until real dimensions are supplied.
- Never fabricate an `.rdk` station or real integration result.
