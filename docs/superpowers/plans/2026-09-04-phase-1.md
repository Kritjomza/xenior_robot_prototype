# Phase 1 Mock Foundation Implementation Plan

**Goal:** Complete the executable mock foundation and all Phase 1 acceptance checks.

**Architecture:** Strict Pydantic models generate JSON schemas and TypeScript types. A single in-memory executor owns run state and publishes snapshots. A mock adapter owns pose, speed and gripper. React consumes HTTP actions and reconnecting WebSocket telemetry.

**Tech stack:** React, TypeScript, Vite, FastAPI, Pydantic, pytest, Vitest and Playwright.

**Spec:** `2026-09-04-delta-robot-web-mvp.md`, Phase 1 only, plus the user's acceptance criteria.

## Constraints and decisions

- Work inline and autonomously as requested. Preserve the supplied plan unchanged.
- Mode is always `mock`. No hardware, RoboDK, Blockly, Monaco, DSL or kinematics.
- Units: millimetres, mm/s, degrees, seconds. Home: (0, 0, -200) mm.
- Strictly positive speeds and waits; waits capped at 3600 seconds per command.
- Command IDs required and unique; 1–1000 commands; unknown fields rejected.
- Add `POST /api/v1/reset` to cancel any active run and restore home, default speed, released gripper and clear run/error metadata atomically.
- Moves update mock pose immediately; joints remain zero and fourth rotation axis is unsupported.
- One API process/worker. Memory-only state. Latest run only. Full WebSocket snapshots with monotonic revisions and periodic refresh.
