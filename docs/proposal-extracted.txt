2.1 ทฤษฎีคิเนเมติกส์ของหุ่นยนต์แบบขนาน (Kinematics of Parallel Robots)  
 หุ่นยนต์แบบขนาน (Parallel Manipulator) แตกต่างจากหุ่นยนต์แบบอนุกรม (Serial Robot) โดย
มีสายโซ่จลนศาสตร์หลายเส้นเชื่อมต่อระหว่างฐานที่อยู่กับที่และแพลตฟอร์มเคลื่อนที่ แทนการเชื่อมข้อต่อ
เรียงต่อกันเป็นสายเดียว โครงสร้าง Rotary Delta ประกอบด้วยแขนสมมาตร 3 ชุด แต่ละชุดขับเคลื่อนด้วย
ข้อต่อหมุนที่ติดตั้งบนฐานอย่างอิสระ และใช้ก้านแขนแบบสี่เหลี่ยมด้านขนาน (Parallelogram Linkages) 
เพื่อรักษาทิศทางของแพลตฟอร์ม ทําให้แพลตฟอร์มเคลื่อนที่ในแนวแกน X, Y และ Z โดยไม่เกิดการหมุน 
(Pure Translational Motion) 
ตัวแปรทางเรขาคณิต (Geometric Parameters): 
● 𝑅 = รัศมีของฐานมอเตอร์ (Base radius) 
● 𝑟 = รัศมีของชุดจับชิ้นงาน (End-effector radius) 
● 𝐿! = ความยาวต้นแขน (Bicep) 
● 𝐿" = ความยาวปลายแขน (Forearm / Parallelogram linkages) 
● 𝛩# = มุมที่มอเตอร์แต่ละตัวต้องหมุน (Actuation angle) 
● (𝑥,𝑦,𝑧)	= พิกัดเป้าหมายของหัวหยิบ 
 
 
 
 
 
 
 
 
 
รูปที่ 2.1 แบบจําลองเรขาคณิตของแขนหนึ่งชุดในหุ่นยนต์ Delta Robot

การวิเคราะห์คิเนมาติกส์สําหรับ Delta Robot จะแบ่งออกเป็น 2 ส่วนหลักดังนี้: 
2.1.1 คิเนเมติกส์ย้อนกลับ (Inverse Kinematics: IK) 
IK คือการหาค่ามุมมอเตอร์ theta ทั้ง 3 ตัว เมื่อทราบพิกัดเป้าหมาย (x, y, z) 
สมการข้อจํากัดทางเรขาคณิตเริ่มต้นจากการหาพิกัดจุดต่อระหว่างต้นแขนและปลายแขน 
(จุดข้อศอก) จากนั้นสร้างสมการทรงกลมที่มีรัศมี L2 โดยมีจุดศูนย์กลางอยู่ที่ End-effector offset 
เมื่อแก้สมการตรีโกณมิติจะได้รูปแบบความสัมพัธ์มาตรฐาน: 
𝐸𝑐𝑜𝑠𝛩#+𝐹𝑠𝑖𝑛𝛩#+𝐺=0	 
ค่าพารามิเตอร์ 𝐸,𝐹,𝐺	จะถูกคํานวณมาจากพิกัดเป้าหมาย (𝑥,𝑦,𝑧) และสัดส่วนโครงสร้าง 
(𝑅,𝑟,𝐿!,𝐿") ของหุ่นยนต์ จากนั้นจะสามารถหาค่า 𝛩#ได้ด้วยสมการ:

เพื่อให้ระบบมีความปลอดภัยและตอบสนองต่อคําสั่งแบบกึ่งอัตโนมัติ (Cartesian Jogging)

• IDLE / HOLD State: มอเตอร์รักษาสถานะล็อคตําแหน่ง (Holding Torque)

• HOMING State: กระบวนการเริ่มต้นเพื่อเคลื่อนที่กลับสู่จุดอ้างอิงศูนย์ (Absolute Zero) 
โดยอาศัยการอ่านค่าจากเซนเซอร์ Limit Switch เพื่อรีเซ็ตค่าพิกัด 
• JOGGING State: โหมดการสอนจุดทํางาน (Manual Teaching) ที่ระบบจะรับคําสั่งพิกัด 3 
มิติทีละสเต็ปจากผู้ใช้ นําไปผ่านสมการคิเนมาติกส์ และขับมอเตอร์ทันที 
• ERROR State: 
สถานะหยุดทํางานฉุกเฉินเมื่อซอฟต์แวร์ตรวจพบการสั่งงานที่เกินขอบเขตพื้นที่การทํางาน

2.5.3 Design and Implementation of a Real-time Motion Control System based on

Operating System: FreeRTOS) สําหรับระบบควบคุมการเคลื่อนที่ความเร็วสูง เพื่อแก้ปัญหา
ความหน่วงเวลา (Latency) และการสูญเสียจังหวะสัญญาณสเต็ป (Lost Steps) อันเนื่องมาจากความ
แปรปรวนของเวลาประมวลผล (Timing Jitter) 
• การจัดสรรงานตามระดับความสําคัญ (Task Prioritization Architecture) 
งานวิจัยได้แบ่งกระบวนการทํางานภายในไมโครคอนโทรลเลอร์ออกเป็น 3 ลําดับชั้นอย่างเป็น
อิสระ: 
1. Hardware Timer Interrupt (Highest Priority): ทําหน้าที่สร้างสัญญาณพัลส์
ควบคุมมอเตอร์ (Step/Direction Generation) ที่ระดับเวลาจริงแบบขัดจังหวะ มี
ความแม่นยําระดับไมโครวินาที ทําให้สัญญาณขับมอเตอร์มีความราบเรียบสมํ่าเสมอ 
2. Motion Planning Task (Medium Priority): ทําหน้าที่ดึงข้อมูลพิกัดเป้าหมายจาก
คิวข้อมูล (Message Queue) มาคํานวณสมการคิเนมาติกส์ย้อนกลับและวางแผน
โปรไฟล์ความเร็ว (Trajectory Planning / S-Curve) 
3. Communication Task (Low Priority): ทําหน้าที่จัดการรับส่งแพ็กเกจข้อมูล
อนุกรม (Serial/UART Telemetry)

3.3.1 องค์ประกอบของระบบหุ่นยนต์  
• โครงสร้างหลัก: เฟรมอะลูมิเนียมโปรไฟล์สําหรับรองรับกลไกและลดการสั่นสะเทือน 
• แผ่นฐานยึดมอเตอร์: ติดตั้งด้านบนและจัดวางมอเตอร์สามตัวห่างกัน 120 องศา 
• ชุดขับเคลื่อน: สเต็ปเปอร์มอเตอร์ NEMA 23 สามตัวควบคุมการเคลื่อนที่ร่วมกัน 
• ต้นแขน: เชื่อมต่อกับเพลามอเตอร์เพื่อถ่ายทอดการหมุนไปยังก้านแขน 
• ปลายแขน: ก้านคาร์บอนไฟเบอร์คู่ขนานสามคู่ เชื่อมต้นแขนกับแพลตฟอร์มและรักษาแนว
ระนาบ 
• ข้อต่อ: ใช้ Rod Ends รองรับการเปลี่ยนมุมของก้านแขนในสามมิติ 
• แพลตฟอร์มปลายแขน: รองรับหัวจับสุญญากาศและรักษาระนาบขนานกับฐาน 
• ฐานพื้นที่ทํางาน: รองรับกระดานหมากรุกหรือชิ้นงานสําหรับการหยิบและวาง 
3.3.2 ระบบขับเคลื่อนและการควบคุมการเคลื่อนที่  
ใช้สเต็ปเปอร์มอเตอร์ NEMA 23 จํานวนสามตัวขับต้นแขนโดยตรง ร่วมกับวงจรขับที่รับ
สัญญาณ Step และ Direction จากไมโครคอนโทรลเลอร์ และใช้ Microstepping ช่วยให้การ
เคลื่อนที่ราบรื่น ไมโครคอนโทรลเลอร์รับพิกัดเป้าหมายจากเว็บผ่าน Raspberry Pi แล้วคํานวณ 
Inverse Kinematics เพื่อกําหนดมุมมอเตอร์และควบคุมทั้งสามแกนให้เคลื่อนที่สัมพันธ์กัน

3.3.4 การทํางานร่วมกับ RoboDK Digital Twin

สถานะกับฮาร์ดแวร์จริง โดยแบ่งการทํางานออกเป็นสามส่วน ได้แก่กระบวนการทํางานและ

• การปรับสถานะผ่าน API: ชุดควบคุมส่งข้อมูลตําแหน่งหรือมุมแกนกลับมายัง Backend 
ซึ่งใช้ RoboDK Python API ปรับสถานะของแบบจําลองตามข้อมูลที่ได้รับ โดยแยก
ข้อมูลที่คํานวณจากคําสั่งออกจากข้อมูลที่วัดจากฮาร์ดแวร์ 
• การแสดงผลบนเว็บ: หน้าเว็บใช้โมเดล GLB ที่แยกชิ้นส่วนสําหรับการเคลื่อนที่ และรับ
ข้อมูลสถานะจาก Backend ผ่าน WebSocket เพื่อปรับโมเดลและแสดงตําแหน่ง มุม

RoboDK
