# Robot protocol V1

The JSON documents are generated from `apps/api/app/domain` with `python apps/api/export_schemas.py`:

- `robot-command.schema.json`: discriminated union of the seven commands.
- `robot-program.schema.json`: `RobotProgramV1` envelope containing commands.
- `robot-state.schema.json`: complete serialized `RobotState` snapshot.

They use JSON Schema draft 2020-12. TypeScript definitions are generated by `npm run generate:types` into `apps/web/src/generated`. Do not hand-edit generated files.

## Program

Required top-level keys: `version` (integer **1**), `name` (1–200 characters), `commands` (1–1000 commands). Unknown keys are rejected everywhere. Command IDs are required, unique within a program, 1–100 characters, using letters, digits, `_` and `-`.

| Type | Additional fields | Meaning |
| --- | --- | --- |
| `home` | none | Restore mock XYZ home and fixed joints; retain speed/grip. |
| `move_xyz` | `x_mm`, `y_mm`, `z_mm`; optional `speed_mm_s` | Immediately update XYZ. Supplied speed becomes the current speed; omitted speed inherits it. Explicit null is invalid. |
| `set_speed` | `speed_mm_s` | Set the current strictly positive speed. |
| `grip` | none | Set gripper state to `gripped`. |
| `release` | none | Set gripper state to `released`. |
| `wait` | `seconds` | Cancellable real-time wait, strictly greater than 0 and at most 3600 seconds. |
| `stop` | none | End this program; subsequent commands never execute. Preserve physical mock state. |

Every command also has `id` and `type`. Numbers must be finite JSON numbers; strings, booleans, arrays and null are not coerced to numbers. NaN, Infinity and overflow such as `1e999` are rejected. Speeds have no artificial upper cap in Phase 1, but must be finite and greater than zero. This is numeric validation, not a physical motion safety assessment.

The server validates the **entire program before scheduling any command**, even if an invalid command occurs after a `stop`. The validate endpoint has no side effects; Run independently validates again.

The API additionally enforces unique command IDs and a Python strict integer version. JSON Schema alone cannot express ID uniqueness, and considers `1.0` equivalent to integer `1`. Raw HTTP `version: 1.0` is rejected; browser JSON parsing normalizes it to `1` before sending. A generated schema default of null on optional move speed describes the internal unset value, not an accepted explicit input. The numeric schema and API both reject an explicit null.

## State

Every HTTP/WS state has all fields, including null metadata when no run is active:

- `version`, increasing `revision`, fixed `mode: "mock"`, adapter `connected`.
- `status`: `idle`, `running`, `stopping`, `completed`, `stopped`, or `faulted`.
- `x_mm`, `y_mm`, `z_mm`, three `joints_deg`, `speed_mm_s`, `gripper`.
- `run_id`, `program_name`, `active_command_id`, `active_command_type`.
- `completed_commands`, `total_commands`, `error` (string or null).

Revisions increase on state changes and remain increasing across Reset in one server process. They restart when the API restarts. The WebSocket sends an initial complete snapshot, subsequent changes, and a full snapshot heartbeat after five seconds without changes. Heartbeats may repeat a revision. A reconnect always gets the current snapshot; this stream is not a durable event log. Each subscriber has a 64-snapshot queue; a slow subscriber loses oldest snapshots, never blocks execution, and still receives the latest state.

The browser distinguishes its WebSocket connection from `connected`, which describes the mock adapter. It labels retained state stale while disconnected, reconnects with delays of 1, 2, 4, 8, then 10 seconds, and treats 15 seconds without a valid snapshot as a lost connection. Valid telemetry resets retry backoff. It never automatically retries a Run request. A disconnect does not cancel a server-side run.
